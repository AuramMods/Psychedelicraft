# Forge 1.20.1 port

## Objective and pinned sources

Port the accepted Forge 1.12.2 implementation and the original 1.20.1 mod functionality to Forge 1.20.1. Each implementation cycle receives a separate commit and push.

The branch is `codex/1.20.1-forge`, created from the accepted commit. The separate worktree is `/Users/cyberpwn/development/workspace/AuramMods/Psychedelicraft-forge-1.20.1`.

## Architecture and migration status

The first cycle replaces the ForgeGradle 3 / Java 8 build and LaunchWrapper coremod with ForgeGradle 6.0.54, Gradle 8.8, Java 17, Forge 47.4.28 and official 1.20.1 mappings. The production jar uses ForgeGradle's `reobfJar`.

Migration is staged. The compiled source now contains all eighteen scalar drug profiles, initial consumables, ten primary crop blocks, natural plant features, drying tables, smoking items/tools, portable fluid vessels, flask/distillery/barrel machines and core gameplay benefit hooks. The other legacy source files and resources remain available in the pinned accepted commit and the original modern commit. Their implementations and regression tests still require migration. The accepted branch's 273 tests provide reference coverage for that work.

The drug capability stores the accepted `Drugs` and `drugInfluences` NBT representation and uses Forge's lifecycle and tracking events. Owner and observer snapshots use a direction-restricted SimpleChannel message. The client defers snapshots until the matching player and dimension exist and clears pending snapshots on logout.

The initial renderer uses a standalone modern PostChain for the donor color-rotation program and a Forge camera-angle event. Shader functions come from the original 1.20.1 resources. Other shader phases, weighted hallucination selection and all remaining effects are pending.

Use Minecraft 1.20.1's native vanilla content for the old backports. The mod-specific interactions still need verification. New 1.20.1 worlds are the target.

## Custom mechanics to preserve

- Nicotine restores two saturation points, or four for a cigar.
- Coffee restores one point per cup and has intensity-scaled speed and reduced saturation exhaustion.
- Cocaine restores one point per second, up to double mining speed and the accepted damage modifier.
- Alcohol reduces saturation exhaustion and incoming damage.
- Mushroom targeting avoidance follows overlapping strength. Local random ticks use the accepted two-to-five block sphere and three-to-eighteen extra ticks per game tick.
- Peyote flight spends saturation only during flight, with the accepted doubled curve and one-point-per-second drain limit.
- LSD retains the smooth reach curve with a seven-block maximum bonus.
- Fresh joints stack, partly consumed joints retain wear, coca seeds require soil and refuse stacked placement, and peyote requires sand.
- Coffee cherries roast, and lower hoppers extract only finished drying-table output.

Implementation anchors are `0ac7e92d`, `0d65421b`, `e7fc247b`, `34920e41`, `b730811f`, `897c25c2` and `17ff1350`.

## Background runtime workflow

`tools/qa` launches Linux Java 17 / LWJGL 3 clients inside Docker under Xvfb. Mesa llvmpipe provides OpenGL 4.5. No client window is created on the macOS desktop. Each client receives a separate game directory, muted master volume, windowed mode, unfocused ticking, four-chunk rendering and a 30 FPS cap. Dedicated servers run with `--nogui`.

Build the image and install the official Forge runtime after building the mod with Java 17:

```sh
docker build --platform linux/amd64 -t psychedelicraft-forge-qa:java17 tools/qa
mkdir -p run/production/cycle1/client run/production/cycle1/server
curl --fail --location https://maven.minecraftforge.net/net/minecraftforge/forge/1.20.1-47.4.28/forge-1.20.1-47.4.28-installer.jar --output run/production/cycle1/forge-installer.jar
java -jar run/production/cycle1/forge-installer.jar --installClient run/production/cycle1/client
java -jar run/production/cycle1/forge-installer.jar --installServer run/production/cycle1/server
cp "$HOME/.gradle/caches/forge_gradle/minecraft_repo/versions/1.20.1/version.json" run/production/cycle1/client/versions/1.20.1/1.20.1.json
```

The launcher merges the installed Forge profile with Mojang's vanilla metadata and downloads the required Linux libraries and assets. An existing Fabric Loom asset cache is an optional read-only source, with `PS_QA_ASSETS` available to select a different cache. Missing assets are downloaded into the isolated install. Parallel client downloads use atomic replacement. Forge's module ignore list includes the installed vanilla jar's filename.

Copy the production mod to the server's `mods` directory. Configure only this test server's EULA, world, bind address and port. The cycle-1 server uses port 25601 and a private flat test world. From its directory, launch:

```sh
java -Xmx2G @libraries/net/minecraftforge/forge/1.20.1-47.4.28/unix_args.txt --nogui
```

Launch clients from the repository root in separate terminals:

```sh
sh tools/qa/run-client.sh run/production/cycle1/client run/production/cycle1/game-owner MushroomOwner owner
sh tools/qa/run-client.sh run/production/cycle1/client run/production/cycle1/game-observer MushroomObserver observer
```

Without the temporary cycle probe these clients open the normal title screen. The ignored `run/production/cycle1/probe` fixture drives normal server connections, item use, capability checks and framebuffer sampling. Probe jars and generated runtime data remain outside tracked production source. Logs and screenshots for this cycle are under `run/production/cycle1`.

Fifteen brew profiles retain their accepted style-selection order, colors, symbols, vinegar handling, fermentation/distillation/maturation stages, alcohol strengths and creative variants. The other twelve profiles retain coffee warmth, drug teas, extracts, injectables and slurry identity. Stage values are clamped at the accepted boundaries when interpreting effects and appearance; arbitrary saved attributes remain intact.
- Keep accepted `fluid:{id,level,attributes}` item NBT and normalize flowing references to source IDs. Read, write and transfer operations copy attributes. Empty attributes normalize to an untagged stack. Saved volume clamps to vessel capacity, and invalid/unknown/negative saved contents read as empty. New 1.20.1 worlds are the target; registry IDs retain the accepted mod names, with additional explicit `flowing_` IDs for native Forge integration.
- Nine portable items preserve accepted capacities, serving quantities, use durations, drink/injection eligibility and container rules. Full plain water/honey in glass and water/lava/milk buckets use native items. Partial contents and brew attributes use tagged mod containers. Names, item data and fluid attributes survive native item replacements. Replacing an item consumes the old single stack and invalidates its capability, preventing cached handles to the prior item from draining retained contents. Direct filling refuses stacked empties; Forge's normal transfer helpers operate on a single working copy.
- Filling recipes use Forge's actual ingredient matcher so named/tagged containers match correctly. Pouring operates on independent single-item copies and returns the changed source as a crafting remainder. Refused, partial and repeated recipe matching preserve the real inventory. Restore ten source filling recipes, six vessel recipes, the bottle recipe and pouring. Morning-glory filling remains pending with that crop/tag.
- The native furnace recipe applies its datapack's fluid identity, minimum quantity, required attributes and arithmetic operations, accepts the legacy coffee `temperature` alias as `warmth`, preserves arbitrary data/volume and refuses unchanged results. Native 1.20.1 furnace `assemble` handles dynamic outputs, replacing the legacy furnace lookup/transformer hooks. Native item-to-item cooking recipes remain the normal mechanism for roasting. Fluid machine items still need to join the vessel interface when ported. Generic non-fluid custom furnace recipes use native item cooking serializers; the vessel-heating serializer handles fluid modifications. Optional Forge milk-fluid identity/interoperability still needs integration verification; crafting/pouring maps the native milk bucket to the accepted milk brew profile.
- Native drinking/injection applies the accepted profiles server-side, awards normal consumption statistics/criteria and drains one full serving. Coffee restores one saturation per 250 mB cup at full hunger, with accepted warmth/caffeine doses; repeated cups add influences through the existing effect system. Creative use preserves volume. The drank-brew criterion hook matches fluid, drink style and maturation; its advancement resources and full runtime criteria audit remain pending.
- Restore the original 1.20.1 vessel models/masks and native item predicates/tints, including dyed bottles. Creative entries retain accepted drink-style ordering, three coffee temperatures, the tequila split and four syringe fillings. Original English/Polish text already supplies vessel/fluid names and tooltips.
- The accepted Forge fluid handler supplies capacity/restriction/serving semantics. Original 1.20.1 supplies native models and recipe declarations. LTS `FluidTransferUtils`/reservoir code uses Fabric transactional wrappers; this port uses Forge item handlers and native simulation, without importing the LTS component/packet-codec compatibility layer. The 1.21.5 data-component implementations likewise require adaptation to Java 17/native 1.20.1 NBT.

A connected compatible native machine receives each byproduct; a missing outlet clears progress, and a full or mismatched outlet pauses without consuming the source. Completion rechecks the receiver and commits its exact byproduct before changing the source.

These authored reaction quantities are preserved rather than treated as accidental transfer loss.
- Shared machine processing retains input/output vessels and progress through saves. Output fills before input drains, at 50 mB per game tick. World east exposes input; west exposes output; vertical/unsided access exposes both; other horizontal faces expose no vessel automation, matching the accepted implementation. Native `WorldlyContainer` and Forge item wrappers both refuse extraction of unfinished vessels. GUI extraction remains available to recover a partial or blocked container manually.
